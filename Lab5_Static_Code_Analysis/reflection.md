\# Reflection – Lab 5: Static Code Analysis



\### 1. What did you learn from this lab?



I learned how static code analysis tools identify code quality, security, and formatting issues without executing a program. Pylint helped improve code quality, Bandit identified security risks, and Flake8 detected formatting violations.



\### 2. Which tool was most useful and why?



Bandit was particularly useful because it identified security-related risks such as unsafe temporary file creation, shell command execution, and weak random number generation. It helped me understand the importance of secure coding practices.



\### 3. What challenges did you face?



The main challenge was understanding the warnings reported by the tools and applying suitable fixes without changing the intended functionality of the parcel tracking application.



\### 4. How did the code improve after analysis?



The code became more readable, maintainable, and secure. The final Pylint score improved to 10.00/10, Bandit reported no active issues, and Flake8 reported no formatting errors.



\### 5. What would you do differently in future projects?



I would integrate static code analysis tools into my regular development workflow and run them frequently to identify issues early.
